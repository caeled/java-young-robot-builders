01 / THINK → ACT → CHECK

Error is the gap to the goal

Subtract the current measurement from the goal. The sign tells you which direction to correct. Negative error means you have gone past the goal in this one-dimensional model.

double goalCm = 100.0;
double positionCm = 80.0;
double errorCm = goalCm - positionCm;

02 / THINK → ACT → CHECK

Choose a bounded correction

Multiplying error by a gain scales the response. Limit the correction so a large error does not command a huge move. Too little gain can be slow; a large gain can overshoot or oscillate. Motor control on hardware needs its own tested units and limits.

double gain = 0.5;
double requestedStepCm = gain * errorCm;
double stepCm = Math.max(-20.0, Math.min(20.0, requestedStepCm));
positionCm += stepCm;

03 / THINK → ACT → CHECK

Close enough can be success

Measurements and floating-point arithmetic are imperfect. A tolerance defines acceptable error; exact equality can make a robot chase tiny changes forever. Also stop at a step limit and report failure if the target was not reached.

int steps = 0;
while (Math.abs(goalCm - positionCm) > 2.0 && steps < 30) {
    // Measure, choose a bounded correction, and update.
    steps++;
}
boolean reached = Math.abs(goalCm - positionCm) <= 2.0;

05 / CHECK → CORRECT

Explain the evidence.

Why should the program report “limit reached” differently from “target reached”?

Check your thinking & mentor notes

Both stop the routine, but only one proves the goal was met. A failure result gives you evidence to adjust the plan.
