MODULE 09 / BUILD · TEST · EXPLAIN

Your Autonomous Mission

I can design a route, test it, record results, and explain an improvement.

Use a browser and a prediction notebook. Java snippets are learning fragments unless labeled as complete programs. The labs run JavaScript models, not Java.

In this mission

1. Define success before coding2. Build a small plan3. Collect evidence and improve4. Try the lab5. Check & correct

01 / THINK → ACT → CHECK

Define success before coding

Your delivery mission starts at (40, 40), facing east, and ends within 5 cm of (140, 120). The field is 200 × 200 cm. A plan must stay in bounds and finish with STOP. Write down the route you expect before running it.

double targetX = 140.0;
double targetY = 120.0;
double toleranceCm = 5.0;

02 / THINK → ACT → CHECK

Build a small plan

A two-leg route is easy to check: 100 cm east, a 90° left turn, then 80 cm north. The snippet uses our imaginary blocking teaching API. Real autonomous programs need hardware configuration and ongoing control updates.

robot.forward(100);
robot.turnLeft(90);
robot.forward(80);
robot.stop();

03 / THINK → ACT → CHECK

Collect evidence and improve

Record the plan, prediction, endpoint, target error, and one change to try next. Our mission runner rejects malformed plans before execution and shows where an otherwise valid route leaves the field. It models an ideal point robot, not obstacles or noisy sensors.

double errorCm = Math.hypot(targetX - xCm, targetY - yCm);
boolean delivered = errorCm <= toleranceCm;
System.out.println("Delivery error cm: " + errorCm);

04 / PREDICT → TEST

Your practice bench

Mission planning lab

Start at (40, 40), facing east. Deliver to (140, 120) within 5 cm. Use one command per line: TURN degrees, DRIVE centimeters, or STOP. Up to 20 commands; turns ±360°, drives ±200 cm. This is a small plan language, not a Java editor.

Predict the result before running.

Results will appear here.
  1. Run the starter route. Explain every coordinate change.
  2. Write a diagonal route using Geometry Bench guidance. Compare path length.
  3. Introduce one wrong turn. Use the trace to diagnose it, then repair just that turn.

05 / CHECK → CORRECT

Explain the evidence.

What would you add before using this plan on a real robot?

Check your thinking & mentor notes

A hardware-specific control program, sensor and motor configuration, obstacle checks, timeouts, tested stopping behavior, and supervised trials. The ideal plan proves geometry, not real-world reliability.

Keep a builder’s notebook.

Write your prediction, result, and one change you tried. Explain why the result changed, using a measurement or trace.
