Java for Robot Builders

I can use decisions, repetition, and named actions to describe a small robot routine.

Use a browser and a prediction notebook. Java snippets are learning fragments unless labeled as complete programs. The labs run JavaScript models, not Java.

01 / THINK → ACT → CHECK

Name the information

A number answers “how much?” A boolean answers a yes/no question. Use names that say what you measured and include units. A distance is not a motor power.

double distanceCm = 35.5;
boolean pathClear = distanceCm > 20.0;

02 / THINK → ACT → CHECK

Choose, then repeat

An if/else chooses one branch. A for loop repeats its body. Trace one pass before predicting the whole routine. Here, three patrol messages appear only when the path is clear.

boolean pathClear = true;
if (pathClear) {
    for (int lap = 0; lap < 3; lap++) {
        System.out.println("Patrol lap " + lap);
    }
} else {
    System.out.println("Wait");
}

03 / THINK → ACT → CHECK

Package an action

A method names a job. Parameters are values the caller supplies; a return value sends an answer back. Small methods make plans easier to read and test.

static boolean isClear(double distanceCm) {
    return distanceCm > 20.0;
}
// Inside main:
boolean canMove = isClear(35.5);

04 / PREDICT → TEST

Your practice bench

Traffic-light & loop lab

Choose a light and repeat count. Predict how many commands the robot will receive. Red and amber wait; only green lets it move.

Predict the result before running.

Results will appear here.
  1. Predict green with 3 repeats, then red with 3 repeats. Run both.
  2. Try 1 and 10 repeats. Explain why counting starts at 0.
  3. Change just the light. Does the number of move commands change?

05 / CHECK → CORRECT

Explain the evidence.

Why does lap < 3 run three times, while lap <= 3 runs four times?

Check your thinking & mentor notes

lap takes 0, 1, 2 for < 3. With <= 3 it also takes 3. Count the values, not just the last number.

Keep a builder’s notebook.

Write your prediction, result, and one change you tried. Explain why the result changed, using a measurement or trace.

Move from a boolean you choose to a measurement you interpret.
