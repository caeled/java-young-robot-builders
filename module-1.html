MODULE 01 / ABOUT 30–45 MINUTES

Meet the
robot brain.

Your mission: give a robot a clear set of steps, predict what happens, and use the result to improve your plan.

You need: a browser, something to jot down predictions, and your curiosity. No Java installation or robot needed.

In this mission

1. Give a command2. Order matters3. Name a number4. Make a decision5. Check your thinking

01 / THINK → ACT

Code is a set of instructions.

A robot doesn’t guess your plan. A program tells it what to do. In our imaginary teaching robot, a method is a named action you can ask for.

robot.forward(20);
robot.stop();

forward(20) means “travel 20 centimeters.” The dot connects the robot to its action, the parentheses hold the distance, and the semicolon ends the command. stop() takes no number.

Try it away from the screen.

Ask a partner to pretend to be the robot. Give three precise instructions. Did “go over there” tell them enough? What measurement would help?

Teaching model: forward(distanceCm) finishes before the next command starts. Real robot libraries may work differently; these examples are not hardware-ready code.

02 / PREDICT → RUN → CHECK

Same commands. Different story.

Start at (0, 0), facing east (right). Your delivery spot is 20 cm east and 20 cm north. Choose a plan below. Before running it, sketch where you think the robot will end up.

robot.forward(20);
robot.turnLeft(90);
robot.forward(20);
robot.stop();

Make a prediction, then run the plan.

Order matters because each command starts where the last one ended. A turn changes your heading; it doesn’t change your position.

03 / THINK

Give a useful number a name.

A variable stores a value. A name makes your intention easier to read, and lets you reuse a value.

int distanceCm = 20;
robot.forward(distanceCm);
robot.turnLeft(90);
robot.forward(distanceCm);
robot.stop();

int stores a whole number. If you change distanceCm to 30, both forward moves become 30 cm. Predict the new final x and y before checking the answer.

Check your prediction

Starting at (0, 0), facing east: the first move reaches (30, 0). The left turn faces north. The second move reaches (30, 30).

04 / SENSE → THINK → ACT

A robot can choose.

A boolean is a value that is either true or false. An if statement uses it to choose an action.

boolean pathClear = true;

if (pathClear) {
    robot.forward(20);
} else {
    robot.stop();
}

If pathClear is true, the robot moves. If it is false, the robot stops. Here we set it ourselves. Later, we’ll use a sensor measurement to help make that decision.

A measurement needs interpretation.

A distance sensor might see a chair, miss a thin leg, or return a noisy reading. “Path clear” is a decision our program makes from evidence.

05 / CHECK → CORRECT

Explain it like a builder.

  1. What is the difference between moving and turning?
  2. How can the same commands reach different places?
  3. Why is distanceCm a helpful name?
  4. What happens when pathClear is false?
  5. If your result differs from your prediction, what one thing will you change first?
Mentor notes & answer hints

Moving changes position; turning changes heading. Command order changes the route. A named variable explains the value and makes it reusable. A false pathClear selects stop(). For debugging, compare the starting heading, order, and distances, then change one thing and test again.
